A. INFORMACIÓN GENERAL DEL PROYECTO
--------------------------------------------------------------------------------

Nombre: NutriKids

Objetivo general:
  Plataforma integral de nutrición infantil que conecta padres, niños,
  nutriólogos y administradores para registrar hábitos, progreso, citas y
  comunicación familiar con enfoque positivo.

Problema que resuelve:
  - Dificultad de los padres para monitorear hábitos alimenticios de sus hijos.
  - Falta de herramientas lúdicas para que el niño participe activamente.
  - Necesidad de un panel clínico para nutriólogos y administración central.

Usuarios principales:
  - Padres (Web Flask + portal + App móvil)
  - Niños (App móvil con PIN)
  - Nutriólogos (Laravel)
  - Administradores (Laravel /admin)

Tecnologías utilizadas:
  - Web pública padres: Flask (Python)
  - Panel admin/nutriólogo: Laravel 11 (PHP)
  - API REST: FastAPI (Python) — contrato /api/v1/*
  - Base de datos: PostgreSQL 15
  - Cache/rate limit: Redis 7
  - App móvil: React Native + Expo (NutriKidsMovil/)
  - Contenedores: Docker + Docker Compose
  - Nube: Railway (servicios desplegados)
  - Monitoreo: Prometheus + Grafana (stack local demo)
  - Gateway/balanceador: Nginx (HTTPS + upstream FastAPI x2)

C. SEGURIDAD
--------------------------------------------------------------------------------

1) HASHING DE CONTRASEÑAS — CUMPLE
   Algoritmo: bcrypt (cost factor 12)
   Dónde:
     - fastapi/app/security/crypto.py (hash_password, verify_password)
     - Laravel Hash::make() / password_verify() en LoginService
   Las contraseñas NUNCA se guardan en texto plano en PostgreSQL.

   Demo:
     - Mostrar columna usuarios.contrasena en pgAdmin: cadena bcrypt ($2y$...)
     - Explicar: "Al login comparamos el hash, no la contraseña literal"

2) VARIABLES DE ENTORNO Y SECRETOS — CUMPLE (con nota demo)
   - .env real está en .gitignore
   - Plantillas: .env.example, fastapi/.env.example
   - FastAPI exige NUTRIKIDS_SECRET_KEY >= 32 caracteres al arrancar
   - Flask exige FLASK_SECRET_KEY >= 32 caracteres
   - Credenciales demo en seeders (solo entornos de prueba)

3) JWT — CUMPLE (API móvil y clientes REST)
   Implementación: fastapi/app/security/crypto.py + auth_service.py
   - Access token: HS256, expira en 15 minutos
   - Refresh token: opaco, rotación, almacenado como SHA-256 en BD
   - Endpoints: POST /api/v1/auth/login, /refresh, /logout
   - Protección RBAC: fastapi/app/security/rbac.py
   - App móvil: NutriKidsMovil/src/services/auth/tokenManager.ts

   Nota: Laravel admin usa sesión web (cookies), no JWT — es panel server-side.

   Demo JWT:
     1. POST http://localhost:8000/api/v1/auth/login
        Body: {"email":"padre@nutrikids.com","contrasena":"Padre123*"}
     2. Copiar access_token de la respuesta
     3. GET http://localhost:8000/api/v1/familia/ninos
        Header: Authorization: Bearer <token>
     4. Repetir con token inválido → 401 Unauthorized

4) HTTPS / SSL — CUMPLE
   Producción Railway:
     - https://nutrikids-sitioweb.up.railway.app (FastAPI)
     - https://nutrikids-flask-production.up.railway.app (Flask)
     - https://nutrikids-laravel-production.up.railway.app (Laravel)
     - Certificado válido gestionado por Railway

   Demo local:
     - Gateway Nginx en https://localhost:9443 (certificado autofirmado dev)
     - HTTP :9080 redirige a HTTPS
     - Header HSTS en FastAPI producción (main.py security_middleware)

   App móvil preview (eas.json):
     EXPO_PUBLIC_API_BASE_URL=https://nutrikids-sitioweb.up.railway.app

5) FIREWALL / RED — CUMPLE (parcial cloud físico)
   Documento: docker/firewall/REGLAS-FIREWALL.md
   - Redis: sin puerto público
   - PostgreSQL: 127.0.0.1 only local; Railway red interna en nube
   - pgAdmin, Prometheus, Grafana: 127.0.0.1 only
   - Gateway Nginx: punto de entrada HTTPS consolidado

   Pendiente externo: reglas ufw/Security Groups del VPS si migran fuera de Railway.

G. INTEGRACIÓN APP → API → BD → WEB
--------------------------------------------------------------------------------

Flujo arquitectónico:
  APP MÓVIL → FastAPI /api/v1 → PostgreSQL → FastAPI → WEB

Ejemplo REAL demostrable — Comentario en Web:
  (Los comentarios se crean desde Web Flask, no desde app móvil;
   la app móvil sincroniza niños, hábitos, retos, mensajes familiares)

Ejemplo REAL — Niño registrado desde App visible en ecosistema:
  1. App móvil (padre): Familia → Agregar niño → guardar
  2. API: POST /api/v1/familia/ninos → PostgreSQL tabla ninos
  3. Web Laravel admin o portal: el niño aparece en listados
  4. App niño: acceso con PIN muestra el perfil creado

Ejemplo REAL — Comentario/discusión Web con respuestas:
  1. Web Flask: login padre → Comentarios o Discusiones
  2. Publicar comentario → Flask proxy → FastAPI → PostgreSQL
  3. Otro padre pulsa "Responder" → respuesta visible en cadena
  4. Verificar en pgAdmin: tablas comentarios / respuestas_discusion

Prueba sincronización (paso a paso evaluadores):
  1. App: login padre, marcar hábito completado hoy
  2. pgAdmin: SELECT * FROM registros_habitos ORDER BY id DESC LIMIT 5;
  3. App: refrescar estadísticas — dato persiste
  (El panel Web admin puede consultar pacientes/ninos vía Laravel)

PREGUNTAS PROBABLES DE EVALUADORES
================================================================================

P: ¿Cómo protegen las contraseñas?
R: "Usamos bcrypt con factor de costo 12. Al registrarse o iniciar sesión,
   la contraseña se hashea o se compara contra el hash en PostgreSQL.
   Nunca guardamos la contraseña en texto plano."

P: ¿Qué es JWT y cómo lo usan?
R: "Es un token firmado que la API entrega al login. Dura 15 minutos.
   La app móvil lo envía en el header Authorization. Si expira, usamos
   refresh token con rotación para obtener uno nuevo sin volver a escribir
   la contraseña."

P: ¿Dónde está la base de datos?
R: "En PostgreSQL. En Docker está en una red privada internal sin acceso
   desde Internet. En Railway está en la red interna del proveedor."

P: ¿Cómo monitorean el sistema?
R: "Con Prometheus recolectando métricas cada 15 segundos y Grafana
   visualizándolas. Medimos peticiones HTTP, latencia, CPU y memoria
   de los contenedores."

P: ¿Qué hace el balanceador?
R: "Nginx recibe las peticiones HTTPS y las reparte entre dos instancias
   de FastAPI con least_conn. Si una cae, la otra sigue atendiendo."

P: ¿La app móvil es diferente a la web?
R: "Sí. Tiene modo niño con PIN, retos gamificados, hábitos diarios,
   notificaciones y navegación móvil nativa. La web es informativa y
   portal padres; la app es la experiencia interactiva del día a día."

P: ¿Cómo se sincronizan app y web?
R: "Ambas usan la misma API FastAPI y la misma base PostgreSQL.
   Lo que guarda la app persiste en BD y puede consultarse desde
   Laravel admin o endpoints web."

P: ¿Usan HTTPS en producción?
R: "Sí. Railway termina TLS automáticamente. La app móvil apunta a
   https://nutrikids-sitioweb.up.railway.app"

P: ¿Cómo validan formularios?
R: "Triple capa: validación en la UI (React Native / JavaScript),
   validación en Flask/Laravel, y validación en FastAPI con Pydantic
   o reglas Laravel."

P: ¿Qué pasa si alguien intenta muchos logins?
R: "Rate limiting: 5 intentos por minuto por IP en login API,
   bloqueo de cuenta tras 5 fallos, y throttle en login Laravel."
